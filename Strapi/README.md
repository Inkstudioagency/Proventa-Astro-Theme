# Proventa — Strapi backend (optional)

The CMS behind the theme's **Blog** and **Case Study** collections. It is
optional: the site in the parent folder ships with a committed snapshot of this
content and builds without it. Run this only when you want to edit content in a
real admin UI.

```bash
npm install
npm run seed        # imports seed-data/*.csv and downloads its images (once)
npm run develop     # http://localhost:1337 — create your admin user
```

Then, from the repo root:

```bash
echo "STRAPI_URL=http://localhost:1337" > .env   # site reads live Strapi
npm run snapshot                                 # freeze it back into the repo
```

## Collections

| Collection | Source CSV | Entries |
| --- | --- | --- |
| Blog | `seed-data/Blog CMS.csv` | 16 |
| Case Study | `seed-data/Case Studies CMG.csv` | 9 |

`npm run seed` replaces every entry and reuses media already in the library, so
it is safe to re-run. Downloaded originals are cached in `.seed-cache/`.

Public `find` / `findOne` are granted automatically on boot (`src/index.ts`), so
the site can read content without a token.

## MCP server

Enabled in `config/server.ts`, served at `/mcp` — see the
[Strapi MCP docs](https://docs.strapi.io/cms/features/strapi-mcp-server).
Set `MCP_ENABLED=false` in `.env` to disable it.

## Notes

- Dev uses SQLite at `.tmp/data.db`. Set `DATABASE_CLIENT=postgres` and the
  matching `DATABASE_*` variables for anything real.
- `.env` is generated by `create-strapi` and is git-ignored — it holds this
  install's secrets. Copy `.env.example` and generate fresh keys before
  deploying anywhere.
